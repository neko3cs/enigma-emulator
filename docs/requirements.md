# 要件定義

## 目的・背景

歴史的暗号機「エニグマ」の暗号化アルゴリズムを Go 言語で実装し、Go 言語を学習すること（`README.md` より）。

## 想定利用者

開発者自身。Go 言語の学習を目的として、実装・実行しながら理解を深める（`README.md` の「Go言語の学習用」より）。

## 機能要件

- 標準入力から英字のみの文字列を受け取り、JSON設定ファイルから読み込んだ鍵（ローター順序・初期位置・リングセッティング・プラグボード配線・リフレクター種別）でエニグマ変換した結果を標準出力に表示する。
  - 受け入れ基準: 同一の鍵設定で変換した結果を、再度同じ鍵で変換すると元の文字列に一致する（暗号化と復号が対称であること）。
- 鍵はソースコードに埋め込まず、JSON設定ファイル（`src/config.json`）から読み込む。設定ファイルの内容を変えることで、コードを変更せずに鍵を変更できる。
  - 受け入れ基準: `config.json` の内容を書き換えて再実行すると、変換結果が変わる。設定ファイルが存在しない、またはJSONとして不正な場合はpanicせず、エラーメッセージを表示して終了する。

## 非機能要件

特に定めない。学習目的の小規模CLIであり、性能・可用性などの数値目標は設定しない。

## スコープ外

- GUI化（コンソール以外の操作画面）
- エニグマ以外の暗号方式への対応
- 外部公開・API化
- 設定ファイルパスをコマンドライン引数や環境変数で変更できるようにすること（`src/config.json` 固定でよいとする）
- 設定ファイルの内容（ローター名の綴りやリング設定の範囲など）のバリデーション強化（現状の `enigma` パッケージ側のpanicで十分とする）

## 用語集

| 用語 | 意味 |
| :--- | :--- |
| ローター (Rotor) | 1文字ごとに内部配線を通して別の文字へ変換し、処理のたびに回転（ステップ）する部品 |
| ノッチ (Notch) | ローターが特定の回転位置に来たときに隣のローターを連動して回転させる、物理的な切り欠き |
| リングセッティング (Ring Setting) | ローターの内部配線と外側の表示文字とのオフセット |
| リフレクター (Reflector) | 信号を折り返し、逆方向にローター群を通す部品 |
| プラグボード (Plugboard) | 変換の前後で指定した文字ペアを交換する配線盤 |
